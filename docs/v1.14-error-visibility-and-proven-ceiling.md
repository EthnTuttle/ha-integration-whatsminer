Status: implemented. ## 1. Error codes: what the miner already knew

Motivation: on 2026-10-17 the house miner raised firmware error 2320 and quietly derated itself to 1224 W while the integration believed the 2649 W plan was running. The firmware knew; nothing here surfaced it. Every poll now also reads v2 `get_error_code` (read-only, no auth, its own connection after the batch, like `status` — the firmware caps concurrent connections). The reply parses defensively (list-of-dicts or bare dict; missing `Msg`, nulls and malformed entries parse to what they can, never raise) into `error_codes: {code: raised-at}` in the coordinator data; a failed read keeps the last known codes rather than blanking anything.

- **Error Code sensor** (diagnostic): state is the newest code (`none` when clean); attributes are the full `codes` map, `count`, and `newest_at`.
- **Notifications:** each *new* `(code, raised-at)` pair raises one persistent notification (`whatsminer_miner_error_<code>`). The firmware timestamps every occurrence, so a code that clears and returns notifies again; a persistent pair does not.
- Every new pair is also **fault evidence** for the proven ceiling (§3).

## 2. External derate

The limit analogue of an error code: the reported `wattage_limit` sits more than `DERATE_MIN_DELTA_W` (100 W) below the last limit *we* sent — nobody here commanded it. Gates, all required: the gap is real (>100 W), we are past the 90 s post-write window (a legacy `adjust_power_limit` restarts btminer and the report lags), the miner is mining (an intentional stop's reading means nothing), and — v3 only — not still tuning; the candidate must then persist for ≥3 polls spanning ≥2 min. Clears after 3 polls back at the commanded limit.

- The reference is `_limit_commanded` — set only by our own `adjust_power_limit` (and restored across HA restarts in legacy mode, where the persisted limit is always one we sent). Telemetry adoption (`_note_regulation_poll`, v3) mutates `_limit_w` only: adopting a derated report as ours would mask the derate.
- Surfaced as `external_derate` on Control Mode and Mining Status, plus a warning log. It is observation, not a wrestle-back: while the flag is set, hold witnessing is suspended, and the flag's arming is fault evidence (§3).

## 3. Proven ceiling

Once fault evidence exists (error code, external derate, collapse undo) within `FLOOR_PROVEN_TTL_S` (7 days), everything that *raises* ambition caps at what the miner has proven it can hold.

- **Witness:** a run hashing ≥15 min (`FLOOR_STABLE_S`) at a power is witness to it — the same creditability rule the floor learner uses. Only raises move `proven_max`; an equal hold refreshes it hourly. The run in progress when the fault arrived is tainted (it says nothing about what still holds) until our next power command opens a clean boundary; an active external derate also suspends witnessing.
- **Cap:** `min(Power Max, proven_max + 250)` with a witness; `max(floor_effective, fault_power - 250)` without one. On an inversion (that fallback under the effective floor) the floor wins, logged once.
- **Applied at:** the daily plan's `top` (with `"; capped by proven max <w>"` appended to `daily_plan_reason` when it clamps), the v2 ceiling-raise target, and the tuned ceiling-lower in `_regulation_tick`. Under `set_miner_power` the delivery target is clamped to the cap too, so a capped raise cannot restart-loop. Unarmed (or the option off) the cap is Power Max: pre-1.14 command traces are byte-identical.
- **Config:** Configure → first step → **Proven ceiling** (default on: re-faulting at the same ambition every day after the firmware has told us it disagrees is worse than a lowered plan). **Observability:** Control Mode gains `external_derate`, `proven_max_w`, `proven_max_at`, `plan_cap`, `plan_cap_armed`.
- **Honest limits:** the witness never expires (hardware only ages downward; a stale witness merely gates the +250 W margin while 7 clean days disarm the cap); a plan computed before the fault holds until its recompute under `daily`; legacy-mode direct PID moves are not capped mid-flight. Restore warns when the cap is still armed across a restart.
