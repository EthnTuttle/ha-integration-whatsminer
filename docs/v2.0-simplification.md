# v2.0 Simplification

**Motivation.** Every layer added in 1.10–1.14 answered one enemy: the v2
`adjust_power_limit` restart cost. Daily plans, `daily_trim`, step bands,
floor learning, strategy machinery — all existed to avoid restarting btminer.
Since 1.11 verified `set.miner.power` on this firmware, power changes are
restart-free, and the restart-era machinery now only fights the loop. Live on
2026-10-17/18 the floor-vs-proven-ceiling precedence produced a stable
disagreement: 1684 W commanded into a miner derated at 1224 W, forever.

**v2.0 control law (the whole thing):**

```
every poll:
    lockout latch (140°F)  → power_off, hold, operator reset
    freeze guard           → blocks/reverses stops
    demand shutoff         → stop/dwell/resume when no zone calls
    safety caps            → chip ≥ cap or supply ≥ soft cap → power_min
    probe lost             → outdoor-reset fallback curve
    otherwise              → PID on the supply probe

    commanded = clamp(output, floor(now), ceiling(now))
    written via set.miner.power (adjust_power_limit only raises/lowers the
    v2 ceiling, or carries a safety clamp during the boot window)
```

**One bounds source.** `floor(now)` and `ceiling(now)` replace the learned
floor, floor episodes, hardware-fault flags, regulation minimum and the
proven-ceiling cap:

- _floor_ = Power Min, or the power of the last uncommanded short run +250 W
  while that fault is fresh (7 days). Crash evidence says "the miner cannot
  hold this low a power".
- _ceiling_ = Power Max, or (highest witnessed hold, else the power that
  faulted) +250 W while fault evidence is fresh. A derate notes the power
  the miner derated **to**, so the cap converges onto what the hardware
  demonstrated instead of looping at the refused value.
- On inversion (floor > ceiling) the ceiling wins down to Power Min: protect
  the hardware, and say so in the log.

**Removed.** Control strategy (`pid`/`daily*`) option, the daily plan,
`daily_trim`, autotune (module, sensor, button, store), floor learning
(episodes, exhaustion, proven_ok), the `power_regulation` option (v3
`set.miner.power` is the only power path; `poll_up_freq` is always on), the
Reset Learned Floor and Reset Autotune buttons (one Reset Fault Memory button
replaces them), and the Autotune/Demand-plan sensors.

**Kept.** PID (vendored), soft start, predictive back-off, setpoint ramp,
Ke feedforward, price/surplus envelope (out_max only), demand shutoff
(`demand_shutoff.py`, untouched), freeze guard, fallback curve, error-code
visibility + notifications, external-derate flag, hashrate-collapse undo,
tuning gates, Braiins pool sensors, firmware update service.
